# Review 006 — sidebar target picker + Simple/Agent guide generation

Reviewer: Fable (`claude-fable-5-1-thinking-xhigh`). Scope: uncommitted working tree vs `dd7ae72`. `pnpm typecheck`, `pnpm lint`, `pnpm test:ci` (562 tests) all pass. Isolation contract verified: `generateSimpleGuide` / `generateAgentGuide` (`src/model/setup.ts`) call only `planIsolation` (stat-only), `readWorkingTreeDiff`/`readDiff`, `writeTextFile`, and `openWorkspaceFile`/`openAgentChat`. No stash, checkout, or ref write happens before Start; Start still goes through the unchanged `startSession`. Legacy `.guide.json` fallback confirmed in `guide-source.ts`.

## Verdict

**Changes needed.** The in-panel picker and the Reatom state machine are structurally sound and the stash contract is intact, but the headline Simple flow is broken on its primary target: a working-tree guide is written from `git diff <base>` (tracked files only, no sidecar) while Start diffs `base..captured-after-commit` (`git add -A`, includes untracked files and the just-written `.tabthrough-guide.json`), so every Simple working-tree walk opens with a "written for a different diff" toast and omits untracked files. Alongside that: Agent silently writes three files into the user's repo, Start in the generate phase trusts any focused guide regardless of scope, `skill.ts` drops Reatom context after an unwrapped `await`, and the new `setup.ts` machine has no tests.

## Findings

### Reatom

- [major] `src/ui/skill.ts:62` `installWorkspaceSkill`: `const bytes = await workspace.fs.readFile(source)` is not wrapped, yet the continuation calls `wrap(peek(ports).ui.writeTextFile(...))` (66-67), `skillInstalled.set(true)` (68) and `notify` (69). Same at `:40` — `skillInstalled.set(await skillPresentIn(...))`.
  Why it matters: after an unwrapped await `top()` falls back to the root frame (`@reatom/core` `wrap` → `top()`), so the command's abort scope and trace are lost; `guard`'s `isAbort` can no longer see a cancelled install.
  Fix: `const bytes = await wrap(workspace.fs.readFile(source))`; `skillInstalled.set(await wrap(skillPresentIn(capability.repoRoot)))`.

- [major] `src/ui/skill.ts:34-41,43-73` + `src/ui/sidebar.ts:120-123`: `refreshSkillInstalled` / `installWorkspaceSkill` are plain async functions that do IO and write `skillInstalled`; the refresh is fired imperatively from a Vue `watch` on *every* sidebar view-model change while idle.
  Why it matters: reatom-review §1/§3 — an idempotent read implemented as an imperative loader, unnamed in traces, not abortable, re-running `fs.access` ×2 per phase change/keystroke; a state-writing async flow that is not a named action.
  Fix: add `fileExists(repoRoot, path)` to `UiPort`; `export const skillInstalled = computed(async () => { const cap = await wrap(gitCapability()); skillEpoch(); ... }, 'setup.skillInstalled').extend(withAsyncData({ initState: false }))`; `installWorkspaceSkill = action(async () => {...; skillEpoch.set(v => v + 1) }, 'setup.installSkill').extend(withAsync())`. Delete the `watch`-driven refresh.

- [major] `src/ui/sidebar.ts:114-129`: the `watch(view, () => {...})` callback calls `resetSetup()` (118) and `refreshSkillInstalled()` (122) without `wrap`, unlike every other bridge callback (`active-guide.ts:46`, `index.ts:66,72,89` use `watchEffect(wrap(...))`).
  Why it matters: reatom-review §2 — external callback touching Reatom state without a frame; runs in root context so the reset is untraceable and can't be scoped.
  Fix: either `watch(view, wrap(() => ...))`, or move "status returned to idle → reset picker" into an `effect` created in `useGuideSidebar` (feature boundary) with `useDisposable({ dispose: unsubscribe })`.

- [minor] `src/model/setup.ts:85,198,222`: `withAsync({ status: true })` on `loadCommits`, `generateSimpleGuide`, `generateAgentGuide` — `.status()` is never read. `loadCommits` also mirrors pending into `setupPhase.loading` by hand (72, 76, 84).
  Why it matters: status model allocated for nothing; duplicated pending flag can desync (see UX finding on a rejected `gitCapability()`).
  Fix: drop `{ status: true }`; derive `loading` in `sidebarViewModel` from `loadCommits.pending() > 0` and remove `loading` from the `commits` phase.

- [minor] `src/model/setup.ts:213`: `resolveGuideFile(peek(guideFile)) || DEFAULT_GUIDE_FILE` — `resolveGuideFile` never returns `''`; dead fallback. And unlike Simple (`:167-171`), Agent never checks `isSafeRepoPath(sidecarPath)`.
  Why it matters: a misconfigured `tabthrough.guideFile` like `../../x.json` is forwarded verbatim into the agent prompt as the path to write.
  Fix: one `resolveSafeSidecarPath(): string | null` used by both generators; refuse with the existing warning.

- [minor] `src/model/view.ts:245,268`: `guideFileName` re-implements `resolveGuideFile` without `normalizeRepoPath` — `./docs/x.json` renders differently from what Simple writes.
  Fix: `guideFileName: resolveGuideFile(guideFile())`.

- [minor] `src/model/setup.ts:224-230` `describeSetupTarget`, `src/model/sidebar.ts:134-140` `describeEntry`, `src/git/types.ts:12` `describeTarget` — three formatters for one union; `src/ui/sidebar.ts:15-17` still whitelists `tabthrough.start/startFromCommit/startFromRange` which `sidebarItems` no longer emits; `src/guide/serialize.ts:46` `STEP_ID_PATTERN.test(id) ? id : ...` is a dead branch (`s\d+` always matches).
  Fix: one `describeTarget` with a `{ short?: boolean }` option; prune the whitelist and the dead branch.

### Safety

- [blocker] `src/model/setup.ts:184-193` Simple working-tree guide is stale by construction. It reads `readWorkingTreeDiff(repoRoot, baseRev)` = `git diff <base>` (`src/git/diff.ts:39-44`, tracked files only) and stamps `scope.diffDigest` from that patch. Start captures with `git add -A` (`src/git/snapshot.ts:43`) and diffs `base..afterCommit` (`src/model/guide-source.ts:73`), a patch that additionally contains every untracked file and the `.tabthrough-guide.json` just written.
  Why it matters: `merge.ts:219-227` flags `stale-guide` → `prompts.ts:133` toasts "The guide was written for a different diff; using it anyway" on every Simple working-tree walk; untracked files are absent from the generated order and fall into trailing `replace` fallback steps (`merge.ts:379`). For this change the three new files (`setup.ts`, `serialize.ts`, `skill.ts`) would be exactly the ones missing.
  Fix: (1) produce the working-tree patch the way Start will see it — reuse the temp-index `read-tree HEAD` / `add -A` / `write-tree` from `snapshot.ts` (no commit, no ref) and call `readDiff(repoRoot, baseRev, tree)`; (2) omit `scope.diffDigest` for `workingTree` scope (the sidecar is inside the diff it describes, so no digest can be stable) and keep it for `commit`/`range`, where `readDiff(base, after)` is identical on both sides; (3) add the integration test named under Tests.

- [major] `src/commands/index.ts:65-69` Agent silently writes into the user's repository: when `skillInstalled` is false it runs `installWorkspaceSkill()`, which writes `.cursor/skills/tabthrough/SKILL.md`, `.agents/skills/tabthrough/SKILL.md` and `.cursor/commands/tabthrough.md` (`skill.ts:65-67`) with no confirmation; the button copy (`sidebar.ts:215`) never mentions it. `skillInstalled` starts `false` (`setup.ts:33`) and is only refreshed asynchronously, so a click that lands before the first refresh overwrites an existing, possibly customised SKILL.md; `.cursor/commands/tabthrough.md` is overwritten unconditionally even when the skill is present.
  Why it matters: unrequested writes into a user's tracked files; possible destruction of a hand-edited skill.
  Fix: `notify('info', 'Agent needs the /tabthrough skill in this workspace…', ['Install and continue', 'Cancel'])` before writing; skip any target that already exists; make `skillInstalled` tri-state (`null` = unknown) and disable Agent until known.

- [minor] `src/model/setup.ts:91-96` `selectCommit` accepts any non-empty webview string and hands it to `git rev-parse --verify --quiet <rev>^{commit}` (`isolate.ts:264` → `diff.ts:59`) and into the agent prompt. `parseRangeInput` refuses whitespace and leading `.`; `selectCommit` refuses nothing.
  Fix: reject revs starting with `-` or containing whitespace; surface the error in the `commits` phase like `range.error`.

- [minor] `src/model/setup.ts:179` Simple refuses only `changedLineCount === 0`; Start also refuses `substantiveLineCount === 0` (`session.ts:662`). A whitespace-only tree gets a guide written and opened, then Start fails.
  Fix: apply both checks in `generateSimpleGuide` and `generateAgentGuide`.

- [minor] `src/ui/ports.ts:191-198` `openAgentChat` string-form fallback auto-submits in upstream VS Code (`work-docs/research/ask-agent-editor-api.md` §"Auto-submit in VS Code"); and on Cursor the object form doesn't throw, so the clipboard fallback is unreachable — if Cursor ignores `isPartialQuery`/`mode` the user sees nothing and gets no clipboard copy. The research only confirms `string` and `{ query }` shapes on Cursor.
  Fix: drop the string fallback (never risk an auto-send); on any failure go straight to clipboard + notice; runbook a manual check that `{ query, isPartialQuery: true, mode: 'agent' }` prefills on the target Cursor build.

### UX

- [major] `src/ui/active-guide.ts:103-107` + `src/model/view.ts:267`: in the `generate` phase Start is shown for *any* valid guide focused anywhere (`guideFocused = focusedGuidePath() !== null`) and `beginFromActiveGuide` uses `phase.target` while ignoring the focused guide's `scope`. The legacy `.guide.json` sitting at this repo root (scope `commit dd7ae72…`) would light up Start for a working-tree target.
  Why it matters: walk starts on target A with a sidecar for diff B → `path-unknown` / `stale-guide` toasts and a heuristic-order walk the user believes is guided.
  Fix: in `generate`, only expose Start when the focused file's repo-relative path equals the resolved sidecar path *or* `loadSidecar(...).doc.scope.kind === phase.target.kind`; otherwise show a row "Focused guide is for a different target" without a button.

- [minor] Start vanishes the moment the guide editor loses focus (`active-guide.ts:46-49`): after Simple opens the file, clicking the terminal, another tab, or the sidebar's own scroll area removes the button with no explanation.
  Fix: in `generate` phase add a `sidecarExists` async computed (port `fileExists`) and offer Start from the known path via `openTextDocument`; keep the focus route as the general case.

- [minor] `res/skill/tabthrough/SKILL.md:14-15,32,44,164` — the copy installed into *user* repos tells the agent to validate against `schema/guide-v1.json` and read `work-docs/architecture/guide-schema.md`, `work-docs/guides/agent-guide-authoring.md`, `test/fixtures/...`, none of which exist outside this repository. Three byte-identical copies (`.cursor/`, `.agents/`, `res/`) with no test or build step guarding drift.
  Fix: bundled skill references only the published `$schema` URL and inlines the "Before you emit" rules; add a unit test asserting the three files are identical, or generate two from `res/`.

- [minor] `src/model/setup.ts:120-125` `gitDiffHint` for working tree is `git diff <base>` — same untracked-file gap as the blocker, now in the agent's instructions.
  Fix: add `git status --porcelain=v1 --untracked-files=all` to the hint block and state "include untracked files".

- [minor] `src/model/setup.ts:72-74` if `gitCapability()` rejects, `loadCommits` leaves `{ kind: 'commits', loading: true }` forever ("Loading recent history…" with only Back); `session.ts` uses `framePromise().catch(wrap(...))` for exactly this.
  Fix: `framePromise().catch(wrap(() => setupPhase.set({ kind: 'commits', commits: [], loading: false })))` at the top of the action.

- [minor] Unrelated churn: `.guide.json` (437 lines) rewritten to describe commit `dd7ae72` while `.tabthrough-guide.json` labels it "Unrelated working copy of a previous walk"; `README.md` command table now lists eight palette-hidden internal commands (`pickWorkingTree`, `selectCommit`, `setupBack`, …).
  Fix: drop `.guide.json` from this change; filter `commandPalette when: "false"` entries out of the README generator.

### Tests
